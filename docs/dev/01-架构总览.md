# 01 架构总览

## 1. 一句话定位

SatDump 是一个"通用卫星数据接收/处理"软件:从 SDR 采集基带(或读录制的基带文件)开始,经 **解调 → 帧同步/FEC → 分包解复用 → 仪器成像 → 产品落盘(dataset.json + product.cbor + 图像)**,再提供 投影/校准/浏览 等后处理。整个应用由「一个核心库 + 若干前端 + 一堆动态插件」构成。

## 2. 分层架构

```
┌───────────────────────── 前端(链接期选择,一个进程只用一个) ─────────────────────────┐
│  src-ui/main.cpp(satdump-ui,桌面)      src-cli/main.cpp(satdump,CLI)     android/main.cpp │
│  GLFW+OpenGL3+NFD+ImGui                CLI11 解析子命令                    EGL/GLES3+ImGui │
│        └─ bindBackendFunctions()        └─ 直接调 satdump_core              └─ bind...() │
├─────────────────────────────── satdump_interface(共用 UI 层) ─────────────────────────┤
│  main_ui.{cpp,h}:initMainUI()/renderMainUI()/exitMainUI(),菜单栏(File/Add/?)           │
│  offline.{cpp,h}:离线处理向导  settings.{cpp,h}:设置页  recorder/:RecorderApplication   │
├────────────────────────────────── satdump_core(核心库) ────────────────────────────────┤
│  init.cpp                        启动编排(配置/插件/流水线/产品/数据库)                 │
│  explorer/ExplorerApplication    主窗口:左侧面板树 + 菜单 + 内容区(由 Handler 填充)     │
│  handlers/(Handler/ProcessingHandler/…)  窗口与处理逻辑抽象,树状子窗口                  │
│  pipeline/                       流水线模型 + 内置模块(demod/ccsds/products/generic…)   │
│  products/ + handlers/product/   产品实体与按仪器分发的处理器                          │
│  dsp/(ndsp 块体系)  image/  projection/  common/  db/  utils/(EventBus/TaskScheduler)   │
│  core/plugin.h|config.h|params.h|backend.h|resources.h|cli/   基础设施                 │
├────────────────────────────────── plugins/(运行时 dlopen) ─────────────────────────────┤
│  卫星支持(*_support:注册 pipeline 模块)  SDR 源  audio sinks  SIMD 扩展  app 插件       │
└───────────────────────────────────────────────────────────────────────────────────────┘
```

要点:

- **核心库不感知具体前端**。渲染、文件对话框等通过 `satdump::backend::` 命名空间内的一组 `std::function` 全局指针完成(`src-core/core/backend.h`),由前端在启动时用 `bindBackendFunctions()` 填充(桌面实现在 `src-ui/backend.cpp`,Android 在 `android/backend.cpp`)。
- **两层扩展机制**:编译期链接(直接改 `src-core`)与运行时插件(动态库 `dlopen`,见 02 章)。绝大多数卫星/设备支持都是插件。
- `satdump_interface` 是 GUI/CLI 共用的"应用壳",并把 Recorder 等做成 `handlers::Handler` 子类挂到 Explorer 上。

## 3. 数据流(处理链)

一次典型接收/处理经历以下阶段,阶段与 `resources/pipelines/*.json` 的 `work` 顺序一一对应:

```
baseband(基带 IQ 文件/SDR 流)
   │  解调模块(pm_demod/psk_demod/dvbs2_demod…,内部使用 ndsp 块)
   ▼
soft(软比特/符号)
   │  FEC 模块(ccsds_conv_concat_decoder / dvbs2 等,输出 CADU/帧)
   ▼
cadu / frames(帧,含加扰解除/RS/卷积)
   │  各卫星 decoder 模块(如 gk2a_uhrit_cadu_extractor、noaa_hrpt_decoder)
   ▼
products(由 xx_instruments 模块生成 dataset.json + product.cbor + 图)
   │  (自动)products_processor:按 instrument 配置的 autogen 预设做校准/投影等
   ▼
用户浏览/后处理(Explorer 打开 dataset,投影、调 LUT、叠加、导出)
```

- 管线 JSON 里 `work` 的每个 key 是一个"处理级别",其 `"module"` 字段是某个已注册模块的 `getID()`。
- 模块间以**文件**为主流传输方式(上一模块输出文件路径传给下一模块);前两级(解调)还支持 `DATA_STREAM` 环形缓冲并行执行(见 02 章 `Pipeline::run`)。

## 4. 启动生命周期(initSatDump)

`src-core/init.cpp` 的 `initSatDump(bool is_gui)` 顺序执行(约 17 步):

1. 初始化国际化(ENABLE_I18N 时,gettext 域 `satdump`);
2. 打印 banner;
3. 决定 `user_path`(win: `%APPDATA%/satdump` 或 `./config`;linux: `~/.config/satdump`;android: `.`);
4. 加载 `satdump_cfg.js` 并打开 SQLite `main.db`;
5. DB 回读语言设置;
6. 按配置初始化日志(文件 sink / 级别);
7. `loadPlugins()` —— 扫描 `./plugins` 与 `LIBPATH/plugins`,dlopen 每个动态库并调用其 `loader()` 工厂与 `init()`,失败依赖最多重试 10 轮;
8. `satdump_cfg.registerPlugins()`(广播 `RegisterPluginConfigHandlersEvent`);
9. `pipeline::registerModules()` —— 注册内置模块后广播 `RegisterModulesEvent`,插件由此追加自己的模块;
10. 从 `resources/pipelines/` 加载并解析全部流水线 JSON;
11. 初始化 OpenCL(可选);
12. 注册 DB 子处理器(Kepler/TLE、IERS)并 `db->init()`;
13. `products::registerProducts()`(广播 `RegisterProductsEvent`);
14. 应用高级设置中的 DSP 缓冲大小覆盖;
15. 打开 SPICE 星历 `spice/de440s.bsp` 供 NOVAS/CalCEPH 使用;
16. 广播 `SatDumpStartedEvent`;debug 构建打印警告;
17. 启动 `taskScheduler` 后台线程。

退出:`exitSatDump()` 仅重置调度器。

## 6. 两个贯穿全库的「基础设施」心智模型

1. **事件总线(EventBus)**:`src-core/utils/event_bus.h`。`register_handler<T>(fn)` 按 `typeid(T).name()` 保存回调,`fire_event<T>(evt)` 广播。所有"插件向内核注册东西"的通道都是它(模块、产品、CLI 命令、配置 UI、校准器、raytracer、菜单元素…)。全局单例 `satdump::eventBus`(plugin.cpp)。
2. **JSON 即协议**:流水线定义、产品元数据(存 CBOR)、模块参数、配置、仪器预设全部是 nlohmann::json;`core/params.h` 的 `EditableParameter` 提供了从 JSON 自动生成 UI 表单/CLI flag 的统一机制。
