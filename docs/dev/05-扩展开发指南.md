# 05 扩展开发指南(模板速查)

> 全部模板以"最小改动、可插拔"为目标;路径均为仓库内相对路径。

## 模板 A:新卫星支持插件(最常见场景)

### A1. 目录结构

```
plugins/mytr_sat_support/
├── CMakeLists.txt                     # 打包 SHARED 库,链接 satdump_core
├── main.cpp                           # Plugin 子类 + PLUGIN_LOADER + 模块注册
└── mytr/
    ├── module_mytr_demod.h/.cpp       # (可选)解调模块:继承 demod::BaseDemodModule
    ├── module_mytr_decoder.h/.cpp     # 帧/数据解码模块:继承 base::FileStreamToFileStreamModule
    ├── module_mytr_instruments.h/.cpp # 仪器成像模块:同样继承 FileStreamToFileStreamModule
    ├── mytr_deframer.h/.cpp           # 帧同步 helper(不注册)
    └── instruments/imager_reader.h    # 单仪器 reader(CCSDS 解析,不注册)
```

配套资源(放在仓库根 `resources/`,而非 plugins 下):

```
resources/pipelines/MyTr.json          # "module" 填模块 getID()
resources/calibration/…                # 校准数据(可选)
```

### A2. 插件入口 main.cpp

```cpp
#include "core/plugin.h"
#include "logger.h"
#include "mytr/module_mytr_decoder.h"
#include "mytr/module_mytr_instruments.h"

class MyTrSatSupport : public satdump::Plugin
{
public:
    std::string getID() { return "mytr_sat_support"; }
    void init()
    {
        satdump::eventBus->register_handler<satdump::pipeline::RegisterModulesEvent>(registerPluginsHandler);
    }
    static void registerPluginsHandler(const satdump::pipeline::RegisterModulesEvent &evt)
    {
        REGISTER_MODULE_EXTERNAL(evt.modules_registry, mytr::MyTrDecoderModule);
        REGISTER_MODULE_EXTERNAL(evt.modules_registry, mytr::MyTrInstrumentsModule);
    }
};
PLUGIN_LOADER(MyTrSatSupport)
```

### A4. 仪器模块套路(以 JPSS 为参考实现)

`plugins/jpss_support/jpss/module_jpss_instruments.cpp`:`ccsds::ccsds_aos::Demuxer` per VCID → `parseVCDU(cadu)` → 按 `vcdu.vcid` 分发 → `demuxer.work(cadu)` 得 `CCSDSPacket` → 按 `pkt.header.apid` 交给各 `reader.work(pkt)`;reader 攒够一条扫描线后写 `image::Image` 到产出的 dataset 目录。FEC/CADU 提取尽量复用内置模块(`ccsds_conv_concat_decoder` 等),别自己重写。

### A5. CMake

```cmake
cmake_minimum_required(VERSION 3.12)
project(mytr_sat_support)
file(GLOB_RECURSE mytr_sat_support_CPPS *.cpp)
add_library(mytr_sat_support SHARED ${mytr_sat_support_CPPS})
target_link_libraries(mytr_sat_support PUBLIC satdump_core)
# 如需复用其它插件(如 xrit):target_link_libraries(... xrit_support) + include 目录
install(TARGETS mytr_sat_support DESTINATION ${CMAKE_INSTALL_LIBDIR}/satdump/plugins)
```

并在 `plugins/CMakeLists.txt` 追加:

```cmake
option(PLUGIN_MYTR "Enable the MyTr support plugin" OFF)
if(PLUGIN_MYTR OR PLUGINS_ALL)
  add_subdirectory(mytr_sat_support)
endif()
```

## 模板 B:内置 pipeline 模块(不建插件)

1. 新建 `src-core/pipeline/modules/<分类>/module_xxx.h/.cpp`(继承处理模块基类,四件套同上);
2. 在 `src-core/pipeline/module.cpp::registerModules()` 加 `REGISTER_MODULE(...)`;
3. 需要的话在 `resources/pipelines/*.json` 引用。CLI 的 `satdump module xxx` 自动可用。

## 模板 C:图像处理函数

1. `src-core/image/processing.h` 声明、`processing.cpp` 实现(自由函数,直接操作 Image);
2. (可选)Angelscript 暴露:`src-core/angelscript/scriptsatdump/bind_image.cpp` 加 `RegisterGlobalFunction`;
3. (可选)UI 接入:`src-core/handlers/image/image_handler.cpp` 加勾选标志并入 `image_needs_processing` 调用链。

## 模板 D:新 UI 窗口 / 菜单项

1. 写 `MyHandler : public satdump::handlers::Handler`,实现 `drawMenu()/drawContents(ImVec2)/getID()`;需要后台任务就再继承 `ProcessingHandler` 实现 `do_process()`;
2. 打开它:`satdump::eventBus->fire_event<satdump::explorer::ExplorerAddHandlerEvent>({ std::make_shared<MyHandler>(), true });`
3. 菜单入口(插件方式):`init()` 里注册 `RenderLoadMenuElementsEvent`,回调中 `ImGui::MenuItem(...)` 命中后 fire 上面的事件(参考 `plugins/tools_app/main.cpp`、`plugins/bitview_app/main.cpp`)。

## 模板 E:新 CLI 子命令

1. 继承 `satdump::cli::CmdHandler`,实现 `reg(CLI::App*)`(add_subcommand + flags)与 `run(app, subcom, is_gui)`;
2. 注册:`eventBus->register_handler<satdump::cli::RegisterSubcommandEvent>([](const auto &evt){ evt.cmd_handlers.push_back(std::make_shared<MyCmd>()); });`

## 通用开发注意事项

- 资源访问一律 `satdump::resources::getResourcePath("…")`;
- 日志用 `logger->info/debug/warn/error/critical(fmt, args…)`(logger.h,slog);
- 模块 UI 用 NOWINDOW_FLAGS 与 `drawProgressBar()`;统计放 `getModuleStats()` JSON;
- Debug 构建自带 `BUILD_IS_DEBUG` 与控制台警告(init.cpp);CMake 会导出 `compile_commands.json`;
- 旧 DSP 代码兼容层在 `src-core/dsp/legacy/(new2old/old2new)`,不建议新代码使用;
- Windows/MSVC 才有 `__declspec(dllexport)` 需求;跨 DLL 边界导出符号用 `SATDUMP_DLL`(见 dll_export.h)。
