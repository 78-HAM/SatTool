# 02 核心子系统:插件 / 事件总线 / 流水线 / 产品 / 配置 / CLI

## 1. 插件系统

### 1.1 基类与入口

`src-core/core/plugin.h`:

```cpp
class Plugin {                    // 所有插件继承它
public:
    virtual std::string getID() = 0;
    virtual void init() = 0;
    virtual ~Plugin() {}
};
```

`PLUGIN_LOADER(constructor)` 宏(plugin.h:10-17)导出唯一的 C 符号作为工厂:

```cpp
#define PLUGIN_LOADER(constructor) \
    extern "C" { satdump::Plugin *loader() { return (satdump::Plugin *)new constructor(); } }
```

### 1.2 加载流程

`src-core/core/plugin.cpp`:

- `loadPlugin()`:dlopen → dlsym("loader") → `loader()` → 对象 `init()` 后挂入列表(Windows 用 `src-core/libs/dlfcn` 兼容层);
- `loadPlugins()`:依次搜索 `./plugins` 与 `LIBPATH/plugins`,按 `.dll/.dylib/.so` 扩展名递归收集;加载失败的插件放入重试队列,**最多重试 10 轮**,以此解决插件互相依赖(如 `gk2a_support` 链接 `xrit_support`)导致的加载顺序问题。

### 1.3 事件总线

`src-core/utils/event_bus.h`(全局单例 `satdump::eventBus`,定义于 plugin.cpp):

- `register_handler<T>(std::function<void(T)>)`:按 `typeid(T).name()` 存回调;
- `fire_event<T>(T evt)`:对所有同类型回调广播;另有 `fire_event(void*, std::string)` 供调度器用显式名字触发。

**全库事件清单**(插件可注册的扩展点):

| 事件 | 定义处 | 用途 |
|---|---|---|
| `pipeline::RegisterModulesEvent` | pipeline/module.h | 插件注册处理模块(最常用) |
| `products::RegisterProductsEvent` | products/product.h | 注册新产品类型 loader |
| `cli::RegisterSubcommandEvent` | core/cli/cli.h | 注册 CLI 子命令(带 `is_gui`) |
| `config::RegisterPluginConfigHandlersEvent` | core/config.h | 注册插件设置页 |
| `SatDumpStartedEvent` | core/plugin.h | 启动完成通知(插件自检/联网更新) |
| `products::RequestImageCalibratorEvent` | products/image/* | 注册图像校准器 |
| `projection::RequestSatelliteRaytracerEvent` | projection/raytrace/* | 注册 raytracer 投影后端 |
| `explorer::RenderLoadMenuElementsEvent` | explorer/explorer.h | 向"Add"等菜单注入条目 |
| `explorer::ExplorerAddHandlerEvent` | explorer/explorer.h | 动态添加窗口/面板 |
| `explorer::ExplorerLoadFileEvent` / `FileDropEvent` | explorer/explorer.h | 打开文件/拖放接管 |
| `db::AutoUpdateKeplersEvent` / `AutoUpdateIersEvent` | db/… | 触发 TLE/IERS 更新 |

## 2. 流水线系统(pipeline)

### 2.1 模块基类 ProcessingModule

`src-core/pipeline/module.h`:抽象类 `ProcessingModule`,生命周期约定(注释 45-57 行):

```
构造 → setInputType/outputType → init() → [循环 process()] → stop()(流式) → getOutput()
```

- 必须实现:`process()`、`drawUI(bool window)`(ImGui 绘制)、`getIDM()`;静态:`getID()`、`getParams()`(默认参数 JSON)、`getInstance(input_file, output_file_hint, parameters)`。
- 数据形态 `ModuleDataType`:`DATA_FILE`(文件)/ `DATA_STREAM`(`RingBuffer<uint8_t>` 循环缓冲)/ `DATA_DSP_STREAM`(复数流)/ `DATA_NDSP_STREAM`。
- `getModuleStats()` 返回 JSON 统计,供 UI 显示。

**两个常用中间基类**:

1. `pipeline::base::FileStreamToFileStreamModule`(pipeline/modules/base/filestream_to_filestream.h):封装"文件/FIFO 双态、分块循环",提供 `read_data()`/`write_data()`/`should_run()`/`cleanup()`/`drawProgressBar()`,以及 `fsfsm_file_ext`(输出扩展名)与 `fsfsm_enable_output`。**帧解码/仪器模块的标准起点**。
2. `pipeline::demod::BaseDemodModule`(pipeline/modules/demod/module_demod_base.h):内置 file_source、频率偏移、AGC、DC blocker、重采样、SNR 估计与星座图/FFT 瀑布 UI;**解调模块的标准起点**。

### 2.2 注册与获取实例

- `REGISTER_MODULE(module)` 供内核在 `pipeline/module.cpp::registerModules()` 内使用;
- `REGISTER_MODULE_EXTERNAL(registry, module)` 供插件在 `RegisterModulesEvent` 回调里追加;
- `ModuleEntry{ id, params, inst }`(module.h:200);`getModuleInstance(id, …)` 按 id 从注册表实例化。

内置模块(module.cpp):各解调器(pm/psk/fsk…)、`network` 类、`xrit` 解复用、CCSDS FEC(见下)、`products_processor`、generic(soft2hard 等)。其中 CCSDS 通用 FEC 是最常被 pipeline JSON 复用的:`ccsds_conv_concat_decoder`、`ccsds_simple_psk_decoder`、`ccsds_ldpc_decoder`、`ccsds_turbo_decoder`(pipeline/modules/ccsds/)。

### 2.3 Pipeline JSON 格式

`resources/pipelines/*.json`,顶层 key 为 pipeline id,字段:

```json
{
  "noaa_hrpt": {
    "name": "NOAA HRPT",            // 显示名
    "live": [1, 2],                 // live 时执行的 work 步骤下标(可选)
    "frequencies": [["NOAA-18", 1707e6]],  // 自动跟踪用的下行频率表(可选)
    "parameters": { ... },          // pipeline 级默认参数(EditableParameter 格式)
    "work": {                       // ★ 处理链:key=级别名,按顺序执行
      "baseband": {},
      "soft":    { "module": "pm_demod",   "parameters": { "symbolrate": 665400 } },
      "frames":  { "module": "noaa_hrpt_decoder", "parameters": { "deframer_thresold": 10 } },
      "products":{ "module": "noaa_instruments" }
    }
  }
}
```

解析(见 pipeline/pipeline.cpp):

- 支持 `"@include": "xxx.json.inc"` 片段包含(顶层与 work 内);
- `loadPipelines()` 递归读取资源目录全部 `.json`(排除 `.json.inc`),再与用户 `pipelines.json`(`user_path` 下,用 diff 合并 JSON)合并;
- `parsePipelines()` 拿 `work` 里的 `module` id 用 `moduleExists()` 校验,缺失则整条流水线被跳过。

### 2.4 执行 Pipeline::run

文件 `src-core/pipeline/pipeline_run.cpp`:

1. **前两级流式并行优化**:若输入级别为 baseband 且前两步支持 `DATA_STREAM`,则 m1 输出到 `output_fifo`(RingBuffer,1000000 单位),m2 从同一 fifo 读,两个 std::thread 并行跑 `process()`;结束时 `stopReader/stopWriter`。
2. **主循环**:按 `work` 顺序逐模块:实例化 → `init()` → `process()` → `getOutput()` 作为下一模块输入文件;`input_level` 指定入口级别(跳过前面的步骤)。
3. **产品后处理**:输出目录出现 `dataset.json` 且 `satdump_cfg.shouldAutoprocessProducts()` 为真时,自动跑 `products_processor` 模块(按配置预设做校准/投影)。
4. 结束广播 `events::PipelineDoneProcessingEvent`。

参数合并:`prepareParameters()` 用流水线 JSON 的 parameters 覆盖模块 `getParams()` 默认值,最终传给模块构造器。

### 2.5 实时管线 LivePipeline

`pipeline/live_pipeline.h`:`start(stream, pool, server_mode)` 以线程池驱动 `live_cfg` 指定的模块子集(解调+解码,通常只有前 1-3 级),支持 normal/server/client 三种模式;`getModulesStats()` 汇报状态。SDR 采集侧在 `src-cli/legacy/live.cpp` 与 Recorder 里组织。

## 3. 产品体系(products)

### 3.1 类型层次

```
products::DataSet            dataset.json —— 一次采集的顶层组织(satellite_name, timestamp, products_list)
products::Product            (抽象)product.cbor —— 元数据 contents + type
 ├── ImageProduct            type="image",成像产品:多通道 ImageHolder 列表 + 投影/校准配置
 └── PunctiformProduct       type="punctiform",点数据(探空等):时间戳+经纬度+值
```

- `Product::save(directory)`:写 `instrument/product.cbor`(json 转 CBOR);`load(path)` 支持本地文件与 http。
- 自定义产品类型:继承 Product/ImageProduct,构造里设 `type = "..."`,然后通过 `products::registerProducts()`(内置)或 `RegisterProductsEvent`(插件)注册 `PRODUCT_LOADER_FUN(TYPE)` loader。
- `ImageProduct` 细节(image_product.h):每通道 `ImageHolder{abs_index, filename, channel_name, image::Image, bit_depth, ch_transform, wavenumber, polarization, bandwidth, calibration_type}`;可设 `proj_cfg`(投影元数据)/ `calibration`;支持 `save_as_matrix`。

### 3.2 产品处理分发

- `products/product_process.*`:`process_product_with_handler()` 用 `handlers::getProductHandlerForProduct(p)` 找到该产品的处理器,遍历 instrument 配置里 `autogen=true` 的预设逐个执行并 `saveResult`。
- `handlers/` 体系:抽象 `Handler`(树状子窗口)与产品专用 `handlers/product/product_handler.h`(ImageProductHandler/PunctiformProductHandler);插件通过 `RequestProductHandlerEvent` 提供自定义处理器。
- 仪器配置 JSON(如 `resources/elektro/l2_cfg.json`)内含 `presets[]`,每项有名字、处理器参数与 `autogen` 标志。

## 4. 配置与参数系统

- `satdump_cfg`(core/config.h):`main_cfg` = 默认 `sattool_cfg.json` + 用户覆盖;用户改动只写 `user_path/settings.json`,用 `merge_json_diffs`/`perform_json_diff` 做**差异合并**;`saveUser()` 落盘。
- `EditableParameter`(core/params.h):从 JSON `{type,value,name,description,options,units…}` 生成 UI 控件与 CLI 参数;类型含 string/password/int/float/bool/options/path/timestamp/notated_int/color/baseband_type/labeled_options。
- `sattool_cfg.json` 三段:`user_interface` / `satdump_general` / `satdump_directories`;修改 defaults 即可改全局默认行为。
- `checkOutputDirs()`:不可写目录时自动把录音/IO 目录切到 Documents。

## 5. 资源定位

`core/resources.h/.cpp`:`getResourcePath("pipelines/xxx.json")` 优先返回运行目录下 `resources/...`,否则 `RESPATH + "resources/..."`;`RESPATH/LIBPATH` 由 `src-core/satdump_vars.cpp` 按平台探测(exe 目录、`../share/satdump` 等)。跨平台开发时**永远用 getResourcePath 取资源**,不要硬编码路径。

## 6. 数据库

`src-core/db/db_handler.h`:SQLite `user_path/main.db`,两表 `meta`、`user`(键值);`set_user/get_user/get_user_json` 存 UI 状态等。子处理器:`KeplerDBHandler`(TLE/轨道缓存)、`IersDBHandler`(极移/UT1-UTC/闰秒),通过事件触发自动联网更新。

## 7. CLI 框架

`src-core/core/cli/`:

- 基类 `CmdHandler{ cmd, reg(CLI::App*), run(app,subcom,is_gui) }`(subcommand.h),`RegisterSubcommandEvent{ handlers, is_gui }`;
- `CommandHandler`(cli.cpp)基于 CLI11:`require_subcommand()`;内置 `pipeline / dsp_bench`,非 GUI 再加 `script / module / probe / process / hserver`;随后广播 `RegisterSubcommandEvent`,最后逐个 `reg`。
- `ModuleCmdHandler`:遍历 `modules_registry` 为**每个已注册模块**自动生成一个子命令(名字=模块 id,参数=module 参数 JSON)——所以注册一个模块,CLI 自动多一条命令。
- `src-cli/legacy.cpp` 保留旧命令组 `satdump legacy live|record|offline …`(具体逻辑在 src-cli/legacy/*.cpp)。

## 8. pipeline 与 SDR 源如何接

SDR 源同样以插件形式存在(`plugins/sdr_sources/*`),实现 `dsp::SourceDescriptor` 工厂(注册进全局源列表 `dsp::registerAllSources()/getAllAvailableSources()`)。live/record 流程:

- `satdump legacy live <pipeline_id> <outdir> --source airspy --samplerate 6e6 …` → 选源 → `set_frequency/set_samplerate/set_settings` → `start()` 得到 `dsp::SourceDescriptor` 的输出流 → 构造 `LivePipeline`(可选 FFT/Splitter)→ `live_pipeline->start(stream, pool, server_mode)`。
- `satdump legacy record <baseband名> …`:SDR → SmartResampler → Splitter/FFTPan(可选)→ `FileSinkBlock` 落盘。

关键目录:`src-cli/legacy/live.cpp`、`record.cpp`、`sdr_probe.cpp`;Recorder 图形界面版在 `src-interface/recorder/`。
